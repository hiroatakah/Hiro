## 1. プラットフォーム戦略の基礎

### 1.1 二面市場（Two-Sided Market）

**プラットフォームとは、供給側と需要側を仲介し、双方から価値を得る構造です。**

| | OneWay の場合 |
|---|---|
| 需要側 | 導入企業（AIエージェントを使いたい） |
| 供給側 | パートナー・顧客企業（エージェントを作れる） |
| 仲介価値 | 標準・品質保証・決済・信用 |
| 収益 | 需要側から利用料、供給側から手数料 |

**重要：二面市場になるのは EL6（Marketplace）からです。** EL1〜EL5 は一面市場（OneWayが作って売る）です。**この違いを混同すると、まだ一面市場なのに二面市場の施策を打って失敗します。**

### 1.2 ネットワーク効果の種類

| 種類 | 内容 | OneWayでの発現 |
|---|---|---|
| **直接的** | 利用者が増えるほど利用者の価値が上がる | 弱い（企業間でAIを共有しないため） |
| **間接的（クロスサイド）** | 供給側が増えると需要側の価値が上がる | **強い**（エージェントが増えるほど導入価値が上がる） |
| **データ** | 利用データが蓄積するほど品質が上がる | **中〜強**（業種別テンプレートの精度向上） |
| **学習・人材** | 使える人が増えるほど採用・運用が容易になる | **強い**（EL5 認定制度が作る効果） |

> **OneWay が狙うのは、間接的ネットワーク効果と人材ネットワーク効果です。**
> 直接的ネットワーク効果は期待できないため、「利用者数を増やせば勝手に価値が上がる」という発想は通用しません。**供給側（EL3・EL4）と人材（EL5）を意図的に作る必要があります。**

### 1.3 Chicken-and-Egg 問題の5つの解法

**「供給がないから需要が来ない、需要がないから供給が来ない」を突破する定石です。**

| # | 解法 | 内容 | OneWayでの適用 |
|---|---|---|---|
| 1 | **片側補助** | 一方を無料・格安にして先に集める | パートナー年会費を初年度無料にする |
| 2 | **自分で供給を作る** | 胴元が最初の在庫を用意する | **OneWay製エージェント50種を先に作る（EL3）** |
| 3 | **マーキーユーザー** | 象徴的な大口を先に押さえる | 業界大手1社を先に導入し、業界団体で発表させる |
| 4 | **単一サイドから始める** | 一面市場として成立させてから二面化する | **EL1〜EL5 は一面市場。EL6で二面化する** |
| 5 | **狭く始める** | 特定業種・地域に絞って密度を作る | **重点8業種のうち、まず2業種で密度を作る** |

**OneWayの基本戦略は「2 + 4 + 5」の組み合わせです。** 自分で在庫を作り、一面市場で稼ぎながら、狭い業種で密度を作る。二面化はその後です。

## 2. 標準を握る者が勝つ

### 2.1 de facto standard（事実上の標準）の作られ方

```
① 独自の記述形式・設計手法を作る
        ↓
② それを無償で公開する（秘匿しない）
        ↓
③ 他社がそれに合わせて作り始める
        ↓
④ その形式で作られた資産が蓄積する
        ↓
⑤ 標準を変えられなくなる（スイッチングコストの発生）
        ↓
⑥ 標準の管理者が、市場のルールを決める立場になる
```

**②が反直感的ですが決定的です。** 標準は、使われて初めて標準になります。秘匿した仕様は標準になりません。

**OneWay での実装：**

| 公開するもの | 秘匿するもの |
|---|---|
| **エージェント記述仕様**（YAML形式） | 顧客の業務データ・ナレッジ |
| **OneWay AI Architecture Framework**（設計手法） | 個別案件の設計内容 |
| 業種別の適用領域マップ（概要版） | Assessment 報告書の中身 |
| 品質基準・Eval の考え方 | 実装コード |

### 2.2 補完財（Complements）の理論

**自社製品の価値は、補完財が増えるほど上がります。** そして補完財は、安く豊富であるほど良い。

| OneWayの製品 | 補完財 | 戦略 |
|---|---|---|
| Platform（EL2） | エージェント（EL3） | **数を増やす。安くする。他社にも作らせる** |
| Platform（EL2） | 実装能力（EL4） | パートナーを増やす |
| エージェント（EL3） | 認定技術者（EL5） | 認定者を増やす |

> **原則：補完財では儲けようとしません。補完財が豊富であること自体が、本体の価値を上げます。**
> 追加エージェント（月5〜20万円）の価格を欲張らない理由がこれです。

## 3. 認定ビジネスの経済学

### 3.1 認定制度は「収益商品」ではなく「流通装置」

大手クラウド・SaaSベンダーの認定制度（クラウド各社、CRM各社、ネットワーク機器各社など）は、いずれも**受験料単体では大きな収益になっていません。** それでも各社が多額の投資をして維持するのは、次の4つの効果のためです。

| # | 効果 | メカニズム |
|---|---|---|
| 1 | **供給能力の拡大** | 自社が採用しなくても、実装できる人が増えます |
| 2 | **参入障壁** | 認定がなければ提案できない構造にすると、競合が入れません |
| 3 | **人材のロックイン** | 認定者は、転職してもそのエコシステム内で働き続けます。**個人のキャリアが製品に紐づきます** |
| 4 | **正統性の獲得** | 認定制度の存在自体が「これは業界標準である」という社会的証明になります |

### 3.2 認定制度の設計原則

| 原則 | 内容 |
|---|---|
| **需要が先、制度が後** | 受験者がいない資格は、制度自体が笑われます |
| **難易度を下げすぎない** | 誰でも取れる資格に価値はありません。合格率50〜70%が目安 |
| **更新制にする** | 年次更新で、継続的な関係とアップデート受講を担保します |
| **法人格付けと連動させる** | 認定者数がパートナーランク（Silver/Gold/Platinum）を決める設計にします |
| **顧客側にも認定を出す** | 顧客企業内に「OneWayの言葉を話せる人」を作ると、更新率が劇的に上がります |

### 3.3 日本市場における特殊な有効性

**日本企業は、資格・認定・第三者評価を強く信頼します。**

- 稟議書に「認定パートナー」と書けることの効果が大きい
- 情シスの技術審査で、認定者の在籍が実質的な要件になることがある
- **設立年数の浅さ・企業規模の小ささを補う装置として機能します**

> **OneWayのような若い会社にとって、認定制度は「信用を制度で作る」手段です。**

## 4. パートナーエコシステムの類型

| 類型 | 役割 | 収益構造 | OneWayでの位置づけ |
|---|---|---|---|
| **リセラー** | 再販 | 仕切値との差額 | 採用しない（価格統制が効かなくなる） |
| **リファラル（紹介）** | 送客のみ | 紹介手数料10〜15% | **税理士法人・地銀・士業** |
| **SI / 実装** | 実装・運用 | 実装フィー + レベニューシェア15〜20% | **中堅SIer・開発会社** |
| **ISV / 開発** | 補完製品の開発 | Marketplace手数料 | **Y4以降（EL6）** |
| **業務ドメイン** | 業種知識の提供 | 共同提案・レベニューシェア | **業種特化コンサル** |

**OneWayが最初に作るべきは「リファラル」と「SI/実装」の2種です。** リセラーは価格統制が崩れるため採用しません。

### 4.1 パートナーの迂回リスクへの対策

**パートナーは、いつでもOneWayを外して自社で作ろうとします。** これは悪意ではなく経済合理性です。

| 対策 | 内容 |
|---|---|
| **部品を握る** | エージェント（EL3）がOneWay Platform上でしか動かない |
| **土台を握る** | Governance・Knowledge Hub の再現に3年かかる |
| **正統性を握る** | 認定（EL5）がないと顧客に提案できない |
| **経済性を握る** | 迂回して自社開発するより、レベニューシェアを払うほうが儲かる状態を作る |

> **最も強力なのは4番目です。** パートナーが「自分で作るより乗ったほうが儲かる」と計算できる設計にします。

## 5. 参照事例：AWS Marketplace の構造変化

**AWS Marketplace は、この構想における最重要の参照事例です。「ソフトの店」から「エンタープライズIT調達のOS」へ変化した過程に学びます。**

```
第1世代：ソフトウェアを売る場
    ↓  「品揃え」の勝負
第2世代：プロフェッショナルサービスも売れる場
    ↓  ソフト単体では顧客の課題が解けないことへの対応
第3世代：複数製品を束ねたソリューションを売れる場
    ↓  顧客は製品ではなく「解決」を買う
第4世代：契約型・サブスク型・従量課金を自由に組み合わせられる調達基盤
    ↓  「買いやすさ」そのものが価値になった
```

### 5.1 学ぶべき4点

| # | 学ぶ点 | OneWayへの適用 |
|---|---|---|
| 1 | **サービスも商品として流通させた** | パートナーの実装サービスも Marketplace の商材にします |
| 2 | **複数製品をソリューションとして束ねた** | Platform + エージェント + 実装 をワンパッケージで販売します |
| 3 | **課金形態を柔軟にした** | 契約型 / サブスク / 従量 / 併用を顧客が選べるようにします |
| 4 | **調達の摩擦を消すことに価値を置いた** | **エコシステムの価値は「品揃え」より「買いやすさ」にあります** |

### 5.2 出店側としての正しい理解

> **AWS Marketplace は、集客チャネルとしてはほぼ機能しません。**
> **「調達・決裁の摩擦を下げるチャネル」として使うのが正解です。**

| 期待できること | 期待してはいけないこと |
|---|---|
| 新規ベンダー登録・与信審査の省略 | 出品しただけで引き合いが来ること |
| 顧客のクラウドコミット枠への充当（**条件・充当率は要確認**） | 全額が充当できると断言すること |
| Private Offer による個別価格・個別条件の提示 | 公開価格での大型契約 |
| 契約型・従量型の柔軟な課金 | 手数料ゼロ |

**出店前の必須確認事項は [11-open-questions.md](11-open-questions.md) に集約しています。**

## 6. 参照事例：SaaS の価格モデル進化

```
第1世代：ユーザー課金（席数 × 単価）
    ↓  問題：AIは「席」では測れない。使わない席にも課金され、定着率が下がる
第2世代：従量課金（実行回数・処理量）
    ↓  問題：予算が読めない。顧客が利用を抑制する
第3世代：ハイブリッド（固定コミット + 従量 + オプション）
    ↓  現在の主流
```

**Salesforce Agentforce は第3世代の代表例です。** Flex Credits による従量課金（例：60,000円/10万クレジット、240円/会話）に加え、事前購入・事前コミット・都度課金（PayGo）を組み合わせています。
**※ 単価・条件は変動します。提案書への引用前に必ず一次情報を確認してください。**

**OneWay も第3世代を採用します（[06-revenue-model.md](06-revenue-model.md)）。**

### 6.1 AI時代の課金設計における3つの罠

| # | 罠 | 回避策 |
|---|---|---|
| 1 | **ユーザー課金にする** | 使わない席に課金され、顧客が席数を絞り、定着率が落ちます → **部門・全社単位で課金します** |
| 2 | **純粋従量にする** | 予算が読めず、顧客が利用を抑制します → **固定コミット + 従量の併用にします** |
| 3 | **クレジット切れで停止する** | 業務が止まる体験は解約に直結します → **自動追加購入で止めません** |

## 7. Land & Expand と NRR の理論

### 7.1 NRR（Net Revenue Retention）が事業価値を決める

```
NRR = (期首ARR + アップセル + クロスセル − ダウングレード − 解約) ÷ 期首ARR
```

| NRR | 意味 |
|---|---|
| 100%未満 | 新規獲得が止まると縮小します |
| 100% | 新規獲得が止まると横ばい |
| **110〜130%** | エンタープライズSaaSの優良水準 |
| **130%以上** | 新規ゼロでも成長します。企業価値評価が大きく変わります |

**OneWay の NRR 源泉：**

| 源泉 | 寄与 |
|---|---|
| 追加エージェント（EL3） | **最大**（基本料金の+40〜80%） |
| AI Capacity 超過購入 | 中 |
| Level 3 → 4 → 5 の昇格 | **最大**（1,500万 → 5,000万 → 年8,000万） |
| Enterprise Support の追加 | 小〜中 |

### 7.2 Land & Expand が新規獲得より効率的な理由

| | 新規獲得 | 既存拡大 |
|---|---|---|
| CAC | 250〜500万円 | ほぼゼロ |
| 成約率 | 5〜10% | 40〜70% |
| 信頼構築 | ゼロから | 既にある |
| 意思決定期間 | 3〜12ヶ月 | 1〜3ヶ月 |

> **「今年何社取ったか」ではなく「既存◯社を次のLevelに上げられたか」を、経営指標の中心に置きます。**

## 8. 日本市場特有の論点

| 論点 | 内容 | 対応 |
|---|---|---|
| **資格・認定への信頼** | 第三者認定が実質的な取引要件になることがある | EL5を早めに設計する。ISMS取得を計画に組み込む |
| **SIer構造** | 中堅企業は既存SIerに依存していることが多い | SIerを敵にせず、パートナーに転換する（EL4） |
| **稟議文化** | 3〜6ヶ月かかる。文書が意思決定を動かす | **Assessment報告書を稟議書の下書きとして提供する** |
| **与信・企業規模審査** | 設立年数・資本金が見られる | 紹介ルート優先。実績企業名を出せる状態を作る |
| **相見積もり慣行** | 必ず他社比較を求められる | 比較不能なカテゴリで提案する（[01-positioning.md](01-positioning.md) 4.4） |
| **オーナー企業の即決性** | 同族・オーナー系は意思決定が速い | ICPスコアの項目8で加点する |
| **人手不足の深刻さ** | 採用できないことが経営課題の第1位 | **予算の出所をIT予算から採用予算に付け替える** |

## 9. 既存の戦略資産との接続

OneWay には既に `oneway-marketing-os` スキル（ラッセル・ブランソン三部作ベース）があります。本エンタープライズ戦略との対応関係は次のとおりです。

| ブランソンのフレーム | 本戦略での実装 |
|---|---|
| Value Ladder | **6階建て商品ラダー**（[03-product-ladder.md](03-product-ladder.md)） |
| Big Domino | 「AI活用の成否は、誰が設計したかで決まる」（[01-positioning.md](01-positioning.md) 4.3） |
| New Opportunity vs Improvement | 「開発しません。設計します」（[01-positioning.md](01-positioning.md) 4.4） |
| Three Secrets | 想定問答（[07-gtm-playbook.md](07-gtm-playbook.md) 第7章） |
| Perfect Webinar | **Executive AI Briefing**（[03-product-ladder.md](03-product-ladder.md) Level 0） |
| Dream 100 | ICPリスト200社（[02-icp-target.md](02-icp-target.md) 第7章） |
| 販売環境の変更 | 経営会議での最終報告（[07-gtm-playbook.md](07-gtm-playbook.md) 第6章） |
| Owned Traffic | 既存クライアント・Executive AI Camp受講企業 |

**B2C/教育事業のフレームは、そのままB2Bエンタープライズに転用できます。** ただし次の2点だけ違います。

1. **意思決定者が複数いる**（社長・役員・情シス・現場）→ 役職別のメッセージ設計が必要（[02-icp-target.md](02-icp-target.md) 第6章）
2. **煽り・希少性が逆効果になる**（稟議で「急かされた」と記録されると通りません）→ Urgency は使わず、**投資回収期間の機会損失**で語ります
