## 1. 結論：4要素の複合課金モデル

> **固定年間契約 ＋ 従量課金 ＋ オプション。**
> **顧客のAI利用が増えるほど、OneWayの売上も増える構造にします。**

```
┌──────────────────────────────────────────────┐
│ ① 基本料金（Platform Subscription）            │
│    年額 1,200万〜8,000万円                     │
│    → ARRの土台。ここが事業価値そのもの           │
├──────────────────────────────────────────────┤
│ ② AI Capacity（従量）                          │
│    AI実行回数・処理量に応じたクレジット消費        │
│    → 原価を守り、利用拡大を売上に変える           │
├──────────────────────────────────────────────┤
│ ③ Agent（追加エージェント）                     │
│    月5万〜20万円 / Agent                       │
│    → Marketplace の収益源。NRRの主エンジン        │
├──────────────────────────────────────────────┤
│ ④ Enterprise Support（プレミアムサポート）       │
│    年200万〜800万円                            │
│    → 高粗利。大企業ほど必要とします               │
└──────────────────────────────────────────────┘
```

**参照モデル：** Salesforce Agentforce は、Flex Credits による従量課金（例：60,000円/10万クレジット、240円/会話）に加え、事前購入・事前コミット・都度課金（PayGo）を組み合わせた構造を採用しています。
**※ 具体的な単価・条件は変動します。提案書に引用する前に必ず一次情報を確認してください（[11-open-questions.md](11-open-questions.md)）。**

## 2. ① 基本料金（Platform Subscription）

| プラン | 対象 | 年額 | 含むもの |
|---|---|---|---|
| **Department**（Level 3） | 1〜3部門 / 100〜300ユーザー | **1,000〜2,000万円** | Platform + Agent 10〜20種 + Knowledge Hub + Governance + Control Center + 月次伴走 |
| **Enterprise**（Level 4） | 全社 / 500〜2,000ユーザー | **3,000〜8,000万円** | 全機能 + Agent無制限枠 + 全社ガバナンス + SSO/監査API + 専任アーキテクト |
| **Enterprise Agreement**（Level 5） | 全社・グループ | **年3,000〜8,000万円 × 3年** | 上記 + 大容量Capacity + Marketplace枠 + グループ会社展開権 + プレミアムサポート |

**価格決定の変数（この順で見ます）：**

1. **対象ユーザー数**（最も説明しやすい）
2. **対象部門数**
3. **Assessment で算出した経済効果**（1.4億円の効果に対して3,000万円、という提示）
4. 既存IT投資規模

> **価格は「原価 + 利益」で決めません。「顧客が得る経済効果の20〜25%」で決めます。**
> Assessment（Level 1）が必要な理由は、この分母を顧客自身の数字で確定させるためです。

## 3. ② AI Capacity（従量課金）の設計

### 3.1 設計原則

> **従量課金は、まず「原価を守る仕組み」です。次に「利用拡大を売上に変える仕組み」です。**
> **絶対にやってはいけないのは、顧客に利用を抑制させることです。**

| ✅ 正しい設計 | ❌ 間違った設計 |
|---|---|
| 十分な枠を最初から含める | 少ない枠にして超過で稼ごうとする |
| 超過時は自動で追加購入（利用は止めない） | クレジット切れで機能停止させる |
| Control Center で消費状況を常時可視化 | 請求書で初めて超過を知らせる |
| トークン単価を顧客に見せない | 原価をそのまま転嫁する |

> **クレジットが尽きて使えなくなる体験は、解約に直結します。**
> 「止まらない」ことを設計の第一要件にします。

### 3.2 クレジット体系（案）

| 実行の重さ | 例 | 消費クレジット |
|---|---|---|
| 軽 | 議事録要約 / FAQ応答 / 日報集計 | 30 |
| 中 | 提案書生成 / レポート作成 / 求人票作成 | 100 |
| 重 | 契約書レビュー / 大量文書解析 / 経営会議資料 | 300 |

| プラン | 年間同梱クレジット | 追加購入単価 |
|---|---|---|
| Department | 300万クレジット | 100万クレジット = 15万円 |
| Enterprise | 1,000万クレジット | 100万クレジット = 13万円 |
| Enterprise Agreement | 2,500万クレジット | 100万クレジット = 10万円 |

**※ 単価はモデルの仮置きです。** 初号案件の90日実測で原価を確定させ、**粗利率70%を維持できる水準に再設定します**（→ [11-open-questions.md](11-open-questions.md)）。

### 3.3 粗利防衛のルール

| ルール | 内容 |
|---|---|
| **同梱クレジットの原価上限** | 基本料金の **15%** を超えないこと |
| **モデルルーターの活用** | 軽実行は安価なモデルへ自動振り分け（T5の機能） |
| **原価の月次モニタリング** | 顧客別の原価率をControl Centerの内部ビューで常時監視 |
| **アラート閾値** | 顧客別原価率が **20%** を超えたら価格改定またはモデル構成の見直しを検討 |

## 4. ③ Agent（追加エージェント）— NRRの主エンジン

### 4.1 価格体系

| 種別 | 例 | 月額 / Agent |
|---|---|---|
| **汎用Agent** | 議事録 / 日報集計 / FAQ | **5万円** |
| **業種特化Agent** | 不動産問い合わせ / 介護記録 / 店舗報告 | **10万円** |
| **高度Agent** | 契約書レビュー / 経営会議 / 見積 | **20万円** |

**課金単位は「部門・全社での利用」であり、ユーザー単位ではありません。** ユーザー課金にすると、顧客が利用者を絞り、定着率が落ちます。

### 4.2 経済性の現実的な検証【重要】

「50種類のカタログを用意する」の意味を、数字で正しく理解しておきます。

| ❌ 誤った期待 | ✅ 現実的な見立て |
|---|---|
| 50種 × 10万円 = **月500万円 / 社** | 1社が同時稼働させるのは **5〜10種** |
| 年6,000万円の追加収益 | **年600〜1,200万円**の追加収益 |

**カタログ50種は「1社が全部買う」ためではなく、「どの業種のどの部門にも必ず刺さるものがある」ための品揃えです。**

**それでも、この数字は極めて強力です：**

| 基本料金 | 追加Agent（現実値） | 合計 | 対基本料金 |
|---|---|---|---|
| 1,500万円（Department） | +600万〜1,200万円 | 2,100〜2,700万円 | **+40〜80%** |
| 5,000万円（Enterprise） | +1,200万〜2,400万円 | 6,200〜7,400万円 | +24〜48% |

> **追加Agentだけで NRR 140〜180% が実現します。** これがこのモデルの最大の武器です。
> 新規顧客をゼロ社獲得しても、既存顧客だけで年40%成長する構造になります。

### 4.3 バンドル設計（顧客に「細かく取られる」と感じさせない）

| プラン | 同梱Agent | 追加購入 |
|---|---|---|
| Department | コア10種を同梱 | 業種特化・高度Agentは追加 |
| Enterprise | コア10種 + 業種特化5種を同梱 | 高度Agentは追加 |
| Enterprise Agreement | **Marketplace 20種まで使い放題枠** | 枠超過分のみ追加 |

**Level 5 の「使い放題枠」が、3年契約を選ばせる決め手になります。**

## 9. 値引きのルール（これ以外の値引きを禁止します）

| 認める値引き | 条件 | 上限 |
|---|---|---|
| デザインパートナー価格 | 事例公開許諾 + フィードバック + 翌年以降の価格階段を契約書に明記 | 初年度50%まで |
| 複数年コミット | 3年契約（Level 5） | 15〜20% |
| 一括前払い | 年額一括前払い | 3% |
| パートナー経由 | レベニューシェアとの相殺 | 15〜20% |

**禁止事項：**

- 理由のない値引き（「予算が合わないので」は理由ではありません）
- **Assessment（Level 1）の無償提供** — ラダー全体が崩壊します
- 値引きの代わりに機能を追加する（原価が上がり、粗利が二重に毀損します）

> **価格を下げる代わりに、リスクを下げます。**
> 90日オプトアウト条項（初年度、90日時点で価値未実感なら残期間返金）が、値引きに代わる最強のカードです。
